# 目标

在 `/dashboard/overview` 内容最顶部，为管理员及超级管理员展示全站财务和使用统计，参考用户提供截图的今日、本月统计卡片。

用户最新修正：去掉独立“消费金额”卡片，新增由 Agent 选择的有价值指标。采用“请求次数”，最终四项为充值入账、确认收入、用户余额、请求次数。

# 范围

- 采用当前目录与当前分支实施；用户已明确选择 current，保留现有配置和其他未提交修改。
- 今日、本月分别展示四项。余额表示当前全站用户钱包余额，两组显示同一当前值，不作为历史余额快照。
- 日期按 Asia/Shanghai 自然日、自然月计算，区间从开始时刻至查询当前时刻，不计未来记录。
- 充值入账使用成功钱包充值实际增加的额度，按各支付渠道现有单位换算，不直接相加不同币种的实付 Money。兑换码、管理员直接改余额、赠送和邀请奖励不属于支付订单充值；订阅订单镜像不重复计入钱包充值。
- 确认收入为全站已记录消费日志中的用户侧消费额度，包含钱包和订阅产生的消费；不表示支付实收或利润，不统计上游成本，不另设消费金额卡片。
- 请求次数为对应区间全站消费日志笔数，包含零费用调用，不含失败日志；异步任务按现有最终消费记录计一笔，不把日志笔数宣称为 HTTP 请求总数。
- 收入、调用数据受现有消费日志保留范围和日志启用设置影响；界面有简短口径说明，不伪造已清理的历史记录。
- 复用项目卡片、格式化、错误和加载状态，新增文案完成七种语言。

## 目录结构

### 新建

- `model/dashboard_stats.go` — 全站统计读取现有用户、成功充值和消费日志，无新增表、字段或迁移。
- `model/dashboard_stats_test.go` — 统计口径及真实三种数据库的关键行为验证，集中在一个测试文件。
- `web/src/features/dashboard/components/overview/site-stats.tsx` — 页面顶部管理员统计卡片。
- `web/src/features/dashboard/components/overview/__tests__/site-stats.test.tsx` — 权限、展示、错误和响应式行为回归。

### 修改

- `controller/usedata.go` — 管理员统计处理接口。
- `router/api-router.go` — 复用现有管理员权限保护注册统计路由。
- `web/src/features/dashboard/api.ts` — 统计接口调用。
- `web/src/features/dashboard/types.ts` — 响应类型。
- `web/src/features/dashboard/components/overview/overview-dashboard.tsx` — 在内容最顶部接入统计。
- `web/src/i18n/locales/` — 新增文案的七种语言翻译。

### 删除

无

### 明确不建

- 独立账务子系统、历史余额快照、新配置和定时任务 — 本次只读取现有数据。
- 用户搜索及按模型账单表 — 本次目标为概览页顶部全站统计，截图中的查询和明细属于背景。
- 独立消费金额卡片 — 用户最新要求去掉，消费统计由确认收入表达。

# 非目标

不更改钱包余额、支付、预扣费、结算和退款逻辑；不统计支付实收、上游成本或利润；不增加独立账务页面、用户检索、模型明细、历史余额及免扣业务；不追补被清理的历史日志。

# 验收示例

- 管理员和超级管理员进入概览页，在现有引导和个人摘要之前看到全站统计；普通用户不展示、不请求该数据，未登录和无管理员权限的直接接口调用被拒绝。
- 今日、本月按 Asia/Shanghai 的自然日和月初起点分别聚合至当前；跨日、跨月和月初边界正确，未来记录不计入。
- 只有已成功完成的充值按完成时间计入充值入账；待支付、失效和失败订单不计入；支付渠道单位换算与现有钱包入账一致，订阅镜像不重复计入钱包充值。
- 用户余额显示所有未删除用户的当前钱包余额总和，两组均标注当前；空数据为零，禁用但未删除用户仍计入。
- 确认收入统计各区间内全站已记录消费额度，请求次数统计对应消费日志笔数且包含零费用调用、不含失败日志；界面简要解释消费记录口径与日志保留限制，不出现独立消费金额卡片。
- 加载展示占位，失败展示真实错误和可重试入口，不能把失败伪装为零；窄屏不横向溢出，金额按现有设置显示且保留必要精度，数字随语言切换正确格式化，新增文案支持七种界面语言。
- 后端统计行为在真实 SQLite、MySQL、PostgreSQL 实例通过；前端受影响回归、类型检查、lint 和生产构建通过。

# 关键决定

- 在当前目录实施，保持现有开发环境的预览方式。
- 采用请求次数作为第四项，无需引入新业务状态；确认收入与消费金额不重复展示。
- 日期采用当前用户环境的 Asia/Shanghai；余额为当前值，非历史快照。
- 复用现有权限和货币显示能力，不新增独立财务配置。
- 本次为相互关联的单项页面扩展，使用单个 change，无 Supervisor 子任务拆分。
