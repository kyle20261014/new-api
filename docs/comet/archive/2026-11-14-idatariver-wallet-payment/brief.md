# Outcome

在魔丸现有充值页接入 iDataRiver 固定金额、单 SKU、quantity=1 的充值：选套餐、确认售价/币种/到账额度、同页进入官方支付页、回站自动确认到账，并可从原订单继续查询和付款。用户已确认改善的是魔丸充值页的连贯性。

平台显示币种为 CNY 时，保留套餐售价及到账额度的 USD 原值，补充按平台显示汇率折合的人民币参考值，明确仅供参考、实际付款以渠道为准。参考值不改变任何订单或账务数值。

# Scope

复用钱包充值卡片、确认弹窗和订单记录；迁入参考实现的可信查单、订单快照及幂等结算，补齐防重复下单、中断恢复、过期和退款处理。设置页提供启用、密钥、商户、项目、回调域名和固定套餐配置；敏感值仅服务端使用。目标项目尚无该适配，不复制整个旧钱包页面。

- web/src/features/wallet/、web/src/features/system-settings/、web/src/routes/_authenticated/wallet/ — 原位接入套餐、确认、回站参数和历史订单恢复；按仓库真实设置目录接入配置项。

# Non-goals

不做任意金额、组合商品、多数量、优惠券支付、未知手续费估算或真实支付试单；不增加用户发起退款入口，退款仅接收平台退款结果并处理本地账务；不销售“0.1U测试”SKU；不修改生产套餐、配置或部署；不提交推送、合并和发布。生产发布另行组织。

# Decisions

- 用户最新纠正优先：功能分支和 worktree 必须基于 dev。当前分支 feat/idatariver-wallet-payment-dev 从 dev 的 c76ef65749d89d780161528a6ead15162a12aba8 创建；main 基线旧分支保留，不继续使用。
- 维持唯一 Native SDK change/Run：idatariver-wallet-payment。前后端支付与恢复契约紧密耦合，共用同一验收目标，暂不拆 Supervisor Child。
- 商品选中不下单，点击继续才创建；渠道取该订单实际返回的可用渠道。已知订单恢复不再建单。
- 查询失败保留上次确认状态与原订单；轮询结束不等于失败。无可靠查询证据时不显示“未付款”。
- 官方公开接口仅承诺 payUrl；首版同页跳转，payUrl 不当作原生付款码。未知实际付款金额/币种显示待官方确认，不以零金额代替。
- Runtime select --rebind 已保留同一 Run 并绑定 dev 来源新分支，但 Runtime 的 targetBranch 仍记录 main；该字段不授权合并。后续交付前须通过受支持流程核对交付目标，禁止据此向 main 自动合并。
- 用户在群内接受人民币参考展示建议；此次为新增用户可见范围，保留 A1–A10，新增 A11，同一 Run 返回 Shape 后重新展示完整方案确认。平台 USD 时不重复人民币，TOKENS/CUSTOM 不扩展；历史使用订单 USD 快照及当前平台显示汇率。显示换算不使用 priceRatio 或通用折扣，不进入支付请求、订单价格、quota、结算或退款。
- 获取 pay 链接后先在原确认框可读展示实付金额/币种或未知提示，用户再次点击继续支付才同页跳转；切渠道、关闭弹窗、账户/订单状态变化使旧报价失效，拒绝迟到响应和重复跳转。
- 人民币参考依赖现有 /api/status 的有效有限正 usd_exchange_rate；缺失、非法或换算非有限时保留 USD、提示参考值暂不可用且不阻塞支付。正小额保留有效位或明确标注小于阈值，不显示为零、不把抬高后的阈值冒充精确金额。不新增汇率服务或改变全站默认换算策略。

# Constraints and invariants

服务端决定套餐价格/到账额度并保存快照；核查用户归属、商户、项目、SKU、quantity=1、订单原价和折后价；订单商品计价币种为 USD，渠道实付币种独立展示。禁止客户端金额控制入账。回跳、通知正文和前端按钮不是入账凭据；通知触发服务端重新查询。并发重复通知和查单只入账一次，退款沿用可追溯的回收/人工处理语义。

退款沿用参考实现 model/idatariver_order.go:125-200：未入账先收到REFUND，记录before_credit并阻止以后入账；已入账且当前余额足够，事务内一次全额扣回该订单已入账额度并记录recovered；余额不足则不扣任何额度、不产生负余额，记录manual_required，交人工处理。重复REFUND、退款处理后迟到DONE均不再扣款或入账；manual_required也不因后续余额补足自动重扣。数据库失败回滚整个事务并允许重试，不将事务失败记成已处理退款；本次不新增人工退款操作界面。

新接口按项目规则挂载 /api/mowan/idatariver，回站使用目标已有 /wallet；回调域名须为配置的合法 HTTPS 域名，前端不能指定回调地址。复用现有身份鉴权、审计、限流和数据库连接；扩展表使用 mowan_ 前缀、主节点幂等迁移且失败阻止启动；保持 SQLite/MySQL/PostgreSQL 兼容。

生产仅只读：已确认版本 de963c949-idr-11c7f85f、站点 https://mw.vistalineglobal.com。白名单查询未发现商户/项目/回调覆盖行，生产构建默认商户 6ada…fa10、项目 6adb…2493、回调域名同上；与本地参考仓库 a0862ab40 区分。配置的正常档位为 1/10/20/30/50/100 USD；测试 SKU 6ae41bd5a5befc799a109d36 名称0.1U但配置1/1，排除可售配置，不改生产。

官方 /mapi/order/info 返回 NEW/DONE/EXPIRED/REFUND；/mapi/order/pay 返回 payUrl/payCurrency/amount，无原生码字段或链接有效期保证。重新付款先查 NEW 和可用渠道再取新链接，不能把旧链接失效当订单过期。公开 /mapi/order/search 支持关联信息查单，但不能假定创建接口具有幂等键。

# Acceptance examples

1. A1：钱包原入口展示允许销售的固定套餐和支付方式，选套餐不创建订单，点击继续才创建 quantity=1 的单SKU订单；测试SKU不可售，未配置/不可用有明确提示，其他支付方式行为保持兼容。
2. A2：确认框分别展示服务端快照的套餐售价USD、到账额度以及渠道返回的实付金额/币种；不重复应用通用折扣/汇率，未知费用或空值不显示为已确定实付。
3. A3：确认付款后保存原订单标识并同页前往经校验的官方支付URL；回跳恢复对应订单；无链接、非法URL和获取链接失败保留订单并提示重试，不创建替代订单。
4. A4：回站、刷新、重新进入钱包和重新聚焦时自动查询当前账户的待确认订单；查询有限重试，成功后刷新余额和历史记录；退出/切换账户不展示或查询前一账户订单。
5. A5：查询错误/超时与正常待支付状态分开显示；保留原订单及上次已确认状态，自动轮询结束提供手动查询，不能将上述事件直接标为失败、未付款或过期。
6. A6：历史订单可恢复原订单；继续付款前服务端查验用户归属、NEW状态和渠道可用性，再取得支付链接；DONE/REFUND/EXPIRED不可继续付，原链接失效不自动再建单。
7. A7：仅上游确认EXPIRED才展示过期并允许用户主动重新下单；尚无退款处理记录时，迟到DONE经完整核验可一次入账。REFUND在未入账时阻止后续入账；已入账时余额足够一次全额扣回，不足则不部分扣回、不透支并转manual_required；重复REFUND及任何已处理退款后迟到DONE均不再改变余额，manual_required不自动重扣；数据库失败整体回滚可重试。仅接收平台退款，不新增用户发起退款入口。
8. A8：重复点击、重试和并发请求不重复创建同一支付尝试；已取得订单号的所有失败均保留原订单；创建超时结果未知时保留待核实尝试，通过服务端可信关联恢复唯一匹配订单，无法确认时保持待核实且不自动再下单，不承诺平台不存在的幂等能力。
9. A9：伪造回跳/通知、错误订单归属、商户/项目/SKU/数量/金额/币种不匹配、无效渠道均不能触发错误入账；合法成功并发通知/查单仅入账一次，秘密和可用匿名查询凭据不泄露至前端、日志或错误正文。
10. A10：设置页可管理合法配置且密钥脱敏；禁用/错误配置安全失败；三数据库新建/升级/重复启动保持订单与余额完整；七语言、键盘操作、桌面和移动端状态完整，已有钱包支付及订单列表回归通过。
11. A11：平台CNY时，套餐卡片、原确认框及iDataRiver历史金额保留USD售价/到账额度，按有效平台显示汇率补人民币参考值，注明仅供参考、实际付款以渠道为准；USD及TOKENS/CUSTOM不附加人民币。来源缺失、非有限/非正/不可解析汇率或非有限乘积时保留USD并提示参考值暂不可用且不阻塞支付；正小额不得显示为0或把最小阈值冒充精确值。币种、汇率及语言切换同步更新；历史恢复按原USD快照及当前显示汇率；渠道实付的原币种、有效精度及未知提示保持，请求、SKU、quantity、订单价格、quota及结算/退款不受参考值影响。

# Verification expectations

支付平台网络使用可控模拟，不创建生产订单。覆盖创建结果未知、重复回调/并发查单、原订单继续支付、过期及迟到付款、退款、跨账户恢复和金额校验。按AGENTS执行后端三模块vet/build/test及前端typecheck/lint/test/build，并记录真实结果；数据库改动使用真实SQLite/MySQL/PostgreSQL测试新库、存量升级与重复启动。环境缺口如实记录，不计为通过。宿主支持新建可跟踪独立子会话，正式Verifier必须是与Builder不同的新只读会话，按SDK领取和回报全部验收。

旧候选第三轮独立验收为 blocked：A4/A6/A10 尚缺实际余额/历史刷新、真实聚焦、终态/无渠道组合及完整七语言流程证据；不将新增人民币行为记作旧实现缺陷。现有代码及检查保留作历史证据，新增范围实现后提交新候选，由新的独立执行覆盖 A1–A11；新范围失效或缺失的检查须重做，旧结论不能直接称为新需求通过。新增展示回归须覆盖汇率7.25与8切换、非法/缺失汇率、正小额与溢出、历史快照、渠道BTC/CNY/未知、七语言及移动端可读性，并断言请求和账务参数不变。
