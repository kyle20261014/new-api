# 管理员概览全站统计

## 权限与位置

在 `/dashboard/overview` 内容最顶部、现有引导与个人摘要之前增加全站统计。只有管理员和超级管理员展示和请求数据，后端复用现有管理员授权。原有概览功能继续可用。

### Scenario: 管理员访问全站统计

Acceptance: A1

WHEN 管理员或超级管理员打开概览，THEN 顶部出现统计；普通用户不显示且不请求，普通用户和未登录客户端直接调用接口被拒绝。前端隐藏不能代替后端权限控制。

## 时间区间

今日从 Asia/Shanghai 当日 00:00:00 起，本月从同一时区当月 1 日 00:00:00 起，至查询当前时刻。后端验证请求时间边界或自行生成可信范围，不能接收无效或无限跨度而全量扫描。展示更新时间及日期口径。

### Scenario: 自然日和自然月聚合

Acceptance: A2

WHEN 记录分别位于今天之前、本月之前、区间起点和未来，THEN 只计入对应自然日或自然月开始至当前的记录；跨月和月初边界正确，两组不互相混用。

## 充值

充值入账为成功钱包充值增加的额度，按完成时间聚合。单位与现有入账一致：Stripe 使用 Money 乘 QuotaPerUnit；Creem 的 Amount 已为 quota；其他钱包支付使用 Amount 乘 QuotaPerUnit。不将不同币种的实付金额直接相加。现有订阅支付在充值表的镜像不属于钱包充值；兑换码、赠送、邀请奖励和管理员直接改余额不属于支付订单充值。

### Scenario: 仅累计成功钱包充值

Acceptance: A3

WHEN 存在成功、待支付、失败、失效和订阅镜像订单，THEN 只累计区间内成功完成的钱包充值，并正确转换 Stripe、Creem 和其他支付渠道的额度，不重复计算订阅订单镜像。

## 余额

余额为全部未删除用户当前钱包额度总和，包含未删除的禁用用户。今日、本月分组显示同一当前值，明确标注当前；不尝试从消费记录逆算历史余额。

### Scenario: 展示当前全站钱包余额

Acceptance: A4

WHEN 用户具有不同余额和状态，THEN 汇总未删除用户的当前余额，在今日、本月均正确显示；空集合返回零，不显示为某个管理员自己的余额。

## 收入与请求

确认收入为各区间全站已记录消费日志的消费额度，包含钱包和订阅消费，不表示支付实收、上游成本或利润。请求次数为同一区间消费日志笔数，包含零费用调用，不含失败日志；异步任务按最终消费日志计一笔。采用现有日志数据库，不从只保存小时级缓存的 quota_data 假设实时完整数据。统计受日志开关和保留范围影响，界面说明。独立“消费金额”卡片被用户最新要求取消，第四项使用请求次数。

### Scenario: 收入与调用量来自消费记录

Acceptance: A5

WHEN 存在付费、零费用消费和失败日志，THEN 收入累计消费额度，请求次数包含付费和零费用消费但不含失败；今日与本月范围正确，界面简要说明按消费记录统计及日志保留限制，不出现独立消费金额卡片。

## 展示与故障

复用已有卡片、格式化和状态组件，沿用站点货币配置。金额必须保留能够表达小额消费的精度；数值格式根据界面语言使用合法 Intl locale，切换语言时更新。新文案覆盖全部七种语言。窄屏按响应式网格排列，不因长金额或翻译造成横向溢出。首次加载用占位，接口失败显示错误和重试能力；错误不能展示为零收入。

### Scenario: 加载、失败、响应式及多语言

Acceptance: A6

WHEN 数据加载、接口失败或用户切换语言和屏幕宽度，THEN 分别展示加载、可重试错误或正确数据；没有横向溢出，小额金额可读，七种语言完整且数字格式随语言变化。

## 验证

统计查询须支持项目要求的 SQLite、MySQL、PostgreSQL，主库和日志库分别按已有配置访问，不引入 schema 变更。复用现有前端测试工具和检查脚本，验证用户可见契约。

### Scenario: 统计与页面通过必要检查

Acceptance: A7

WHEN 执行必要检查，THEN 新统计查询在真实 SQLite、MySQL、PostgreSQL 实例上得到预期结果；受影响前端回归、类型检查、lint 和生产构建通过。未执行或受阻的检查不能声明通过。
